## 一、快速上手：更新一篇内容的完整流程

无论更新哪个板块，流程都是这四步：

```bash
# ① 本地修改（写文章 / 改配置 / 加图片）
# ② 本地验证（可选但推荐）
pnpm install          # 首次需要
pnpm dev              # 启动本地预览 http://localhost:4321

# ③ 提交推送
git add .
git commit -m "post: 写清楚你改了什么"
git push origin main

# ④ 等待 1-2 分钟，Cloudflare Pages 自动构建上线
#    浏览器强制刷新（Ctrl/Cmd+Shift+R）查看最新版本
```

> 没配本地环境也能更新：直接在 GitHub 网页上编辑文件（铅笔图标）→ Commit changes，同样触发自动构建。适合改错字、发短动态这类轻量操作。

## 二、教程板块（核心板块）

### 功能定位

博客的核心内容资产。体系化技术教程按「**分类 × 系列**」两级组织，是社团对外知识输出的主阵地。目前有 Python（11 篇）、C++（12 篇）、Java（12 篇）三个完结系列。

### 内容说明

- **分类（category）**：横向大方向，决定文章出现在哪个分类页。现有分类：`Python 教程`、`C++ 教程`、`Java 教程`、`网络安全`、`社团动态`、`技术分享`
- **系列（series）**：纵向课程，同系列文章在站内自动聚合、按序号排序，读者可按课程顺序学习
- 每篇教程统一结构：本篇目标 → 分节讲解（含避坑提示）→ 小练习 → 小结 + 下篇预告

### 更新方法

1. 在 `src/content/posts/` 新建 Markdown 文件，命名与 slug 一致（如 `web-tutorial-01.md`）
2. 按模板写 frontmatter：

   ```markdown
   ---
   title: 系列名（N）：本篇主题
   published: 2026-10-29
   description: 一句话摘要（60字内，列表页展示）
   tags: [技术名, 教程]
   category: 技术分享            # 按上方分类表选
   slug: web-tutorial-01         # 与文件名一致，英文短横线
   series: "Web 开发教程"         # 同系列必须一字不差
   seriesOrder: 1                # 系列内序号
   ---
   ```

3. 本地 `pnpm dev` 检查排版 → push 上线

详细的写作规范见 [docs/tutorial-rules.md](./tutorial-rules.md)（系列设计原则、结构模板、安全红线、投稿流程都在里面）。

### 注意事项

- **开新系列先报备**：系列规划（目标/篇目清单）先发社团群讨论，避免撞车
- **series 字符串严格一致**：一个标点不同就会分裂成两个系列
- **代码必须可运行**：发布前本地跑一遍所有示例，附预期输出
- **版权红线**：可参考任何资料的知识体系，但文字/示例/结构必须原创，禁止搬运菜鸟教程、CSDN 等站点内容
- **单篇 1500~3500 字**：太长拆分，保持读者友好
- 修改已发布文章：直接改完重新 push，主题会显示"上次编辑时间"

## 三、动态板块（说说）

### 功能定位

轻量级的内容出口——一段感想、一条通知、一个链接，比文章门槛低得多。适合日常冒泡、活动预告、快讯转发。

### 内容说明

- 展示在导航「社团 → 动态」页面，侧边栏也有最近动态组件
- 每条动态支持标题、描述、标签、心情图标（mood）

### 更新方法

在 `src/content/dynamic/` 新建文件（命名建议 `日期-主题.md`）：

```markdown
---
title: 今晚直播分享会开始啦
published: 2026-10-29
description: 八点开始，链接在正文
tags:
  - 活动
mood: 🎤
---

今晚八点 B 站直播间，主题是 AI 工具实践，不见不散！
```

### 注意事项

- **频率自由**：动态就是随手发的，不用有心理负担
- **不要发敏感信息**：内部会议链接、成员私人信息等不公开的内容禁止上站
- `published` 决定排序，写当天日期即可

## 四、成员板块（主页展示墙）

### 功能定位

社团成员的 GitHub 主页展示墙，每位成员一张卡片，点进去看个人名片和代表项目。入口：导航「社团 → 成员」。

### 内容说明

- 每张卡片 = `src/content/projects/` 下的一个 md 文件
- 卡片封面用 GitHub 头像，详情页含：成员名片（GitHub/身份/仓库数）、在社团的贡献、GitHub 代表项目简介
- `order` 数值越大排越前（**降序**）

### 更新方法（新成员加入）

1. 复制 `src/content/projects/member-marktom.md` 为模板，重命名如 `member-xxx.md`
2. 修改四处：
   - `title`：成员名 / GitHub 昵称
   - `image`：`https://avatars.githubusercontent.com/u/<用户ID>?v=4&s=160`（160 是小尺寸参数，头像显示大小由卡片容器决定，这个参数控制加载体积）
   - `link` 里的 `value`：成员 GitHub 主页 URL
   - `order`：现有成员用 100、99、98… 递减，新成员排后面
3. 正文按模板写名片、贡献、代表项目（项目简介可参考 GitHub 仓库描述扩写）
4. push 上线

### 注意事项

- **展示内容需本人同意**：头像、主页、简介都涉及个人信息，上墙前和本人确认
- **项目简介保持客观**：按仓库实际功能描述，别夸大
- Fork 的项目标注"Fork 自 xxx"，尊重原创

## 五、相册板块

### 功能定位

社团活动的照片墙，按相册分组、瀑布流展示。入口：导航「社团 → 相册」。当前为空，等待第一批社团活动照片。

### 内容说明

- 相册信息配置在 `src/config/galleryConfig.ts` 的 `albums` 数组
- 图片实体放在 `public/gallery/<相册id>/` 目录
- 支持设置封面（`cover.*` 文件）与访问密码（私密相册）

### 更新方法（添加一个相册）

1. 建目录 `public/gallery/activity-2026-10/`，把照片放进去（可放一张 `cover.jpg` 做封面）
2. 在 `galleryConfig.ts` 的 `albums` 数组加一项：

   ```ts
   {
       id: "activity-2026-10",           // 与目录名一致
       name: "十月分享会",
       description: "第一次线下技术沙龙",
       location: "信息楼 301",
       date: "2026-10-29",
       tags: ["活动", "分享会"],
   },
   ```

3. push 上线

### 注意事项

- **照片授权**：发布含人物的照片前征得当事人同意
- **体积控制**：单张照片建议压缩到 500KB 内（可用 tinypng 或 `sips`），整相册别超 20MB
- **格式**：支持 jpg/png/webp/avif/gif，优先 webp
- **私密相册**：内部活动照片可加 `password` 字段设密码，密码私发给成员

## 六、友链板块

### 功能定位

与其他博客/社团的互换链接，是站点的社交名片。入口：导航「社交 → 友链」。

### 内容说明

配置在 `src/config/friendsConfig.ts`，每条友链含：名称、头像、描述、站点 URL、标签、权重（排序用）。

### 更新方法

在 `friendsConfig.ts` 的 `friendsConfig` 数组加一项：

```ts
{
    title: "某某的博客",
    imgurl: "https://example.com/avatar.png",
    desc: "一句话介绍",
    siteurl: "https://example.com",
    tags: ["Blog"],
    weight: 7,        // 数字越大排越前
    enabled: true,
},
```

### 注意事项

- **互换原则**：加友链前先和对方站长打好招呼，最好对方也挂我们的链接（`https://www.cyberpioneer.club`）
- **失效友链定期清理**：每学期检查一轮，打不开的移除或联系站长
- 头像用对方官方提供的，别盗链大图

## 九、公告（侧边栏）

### 功能定位

首页侧边栏置顶的滚动通知条，适合纳新、活动预告、重要变更等**时效性强的全局通知**。

### 内容说明

配置在 `src/config/announcementConfig.ts`：标题、内容、可跳转链接、是否允许访客关闭。

### 更新方法

```ts
export const announcementConfig: AnnouncementConfig = {
    title: "",
    content: "这里写公告内容",
    closable: true,          // 允许访客关闭
    link: {
        enable: true,        // 要不要带跳转链接
        text: "查看详情",
        url: "/posts/xxx/",  // 站内文章或其他 URL
        external: false,
    },
};
```

### 注意事项

- **一条就够**：公告位只有一条，新公告直接覆盖旧内容
- **过期就关**：活动结束后把 `enable` 设为 false 或清空内容，别让过期通知一直挂着
- 全站生效，措辞正式一点

## 十、轮播壁纸（首页 banner）

### 功能定位

首页顶部的氛围大图，桌面端与移动端分别配置，支持多张随机轮播。当前各有一张社团定制 AI 壁纸。

### 内容说明

- 桌面端图：`src/assets/images/DesktopWallpaper/`（宽幅，约 1920×800+）
- 移动端图：`src/assets/images/MobileWallpaper/`（竖幅 2:3，约 1080×1536+）
- 引用列表在 `src/config/backgroundWallpaper.ts` 的 `src.desktop` / `src.mobile` 数组
- banner 上的文字（主标题/打字机副标题/链接图标）在同文件 `homeText` 配置

### 更新方法

1. 新图放入对应目录（命名如 `club-banner-02.jpg`）
2. 在配置数组的**最前面**加一行路径引用
3. push 生效

配图风格与生成提示词参照 [docs/image-prompts.md](./image-prompts.md)（全站统一视觉规范：青绿科技插画风）。

### 注意事项

- **尺寸匹配**：桌面图要宽幅（16:9 左右）、移动图要竖幅（2:3），放错会显示异常
- **控制体积**：单张压缩到 300KB 内，壁纸太大首屏会慢
- banner 文字改动谨慎——主标题是社团名称，别随意改

## 十一、书签导航板块

### 功能定位**

常用工具与资源站点的导航集合页。入口：导航「社团 → 书签导航」。当前配置了少量技术站点。

### 内容说明

配置在 `src/config/booknavConfig.ts`：多个分组，每组含多个书签（名称/URL/图标/描述）。

### 更新方法

在对应分组的 `items` 里加一项，或新增分组：

```ts
{
    name: "工具",
    icon: "material-symbols:build",
    desc: "常用在线工具",
    weight: 80,
    items: [
        {
            title: "新工具名",
            url: "https://example.com",
            desc: "一句话说明",
            icon: "material-symbols:handyman",
            weight: 10,
        },
    ],
},
```

### 注意事项

- **只收优质常用站**：宁缺毋滥，加之前问一句"社团成员真会常用吗"
- **图标名用连字符**：iconify 格式如 `material-symbols:xxx`，用下划线会导致构建失败
- 链接失效时及时移除

## 十二、站点全局配置速查

日常一般不动这些，但要知道在哪：

| 配置文件 | 管什么 | 动它的时机 |
| --- | --- | --- |
| `src/config/siteConfig.ts` | 站点标题/描述/关键词/导航开关 | 站点定位级变更（需全员讨论） |
| `src/config/navBarConfig.ts` | 导航菜单结构与名称 | 增删栏目时 |
| `src/config/profileConfig.ts` | 侧边栏头像/名称/签名/社交链接 | 换主页链接、换头像 |
| `src/config/sidebarConfig.ts` | 侧边栏组件开关与排序 | 想调整侧边栏内容时 |
| `src/config/backgroundWallpaper.ts` | 壁纸与 banner 文字 | 见第十节 |
| `src/config/musicConfig.ts` | 背景音乐（当前关闭） | 想开音乐时配歌单 |
| `src/config/analyticsConfig.ts` | 访问统计（如需接入） | 想看流量数据时 |
| `src/config/commentConfig.ts` | 评论系统（当前未启用） | 开评论前群内讨论选型 |

> 改任何 `src/config/` 下的文件后，本地跑一次 `pnpm build` 确认没改坏再 push——配置文件语法错误会导致自动构建失败，线上停留旧版本。

## 十三、附录：常见问题与规范汇总

### Q1：push 之后线上没更新？

- 检查 GitHub 仓库最新 commit 是否包含你的改动
- 到 Cloudflare Dashboard → Workers & Pages → 项目 → Deployments 看构建状态（需管理员权限）
- 构建失败最常见原因：Markdown frontmatter 语法错误、配置文件 TypeScript 语法错误、iconify 图标名下划线

### Q2：文章里的图片放哪？

`src/content/posts/images/` 下建与文章同名目录，正文相对路径引用 `./images/xxx.png`。构建时会自动压缩优化。

### Q3：commit message 怎么写？

遵循 Conventional Commits：`post:` 文章、`feat:` 新功能、`fix:` 修复、`docs:` 文档、`chore:` 杂项。示例：`post: Web教程(二)HTML基础`。

### Q4：想下线一篇文章？

把文件里的 `published` 改到未来日期不行——正确做法是删除文件或给 frontmatter 加 `draft: true`（转草稿）。

### Q5：内容红线（必读）

1. **服务器运维信息不上站**：IP、账号、内部路径不写入仓库与文章
2. **安全类内容限合法场景**：漏洞利用教程必须限于靶场/授权测试，附免责说明
3. **个人隐私需授权**：照片、主页、真实姓名上站前征得本人同意
4. **版权**：文字原创，图片自备（AI 生成或授权素材），不搬运第三方站点内容

### 日常维护节奏建议

| 频率 | 事项 |
| --- | --- |
| 随时 | 动态、文章更新 |
| 每月 | 检查友链有效性、公告是否过期 |
| 每学期 | 关于页信息核对、教程总览表更新、成员墙信息核对 |
