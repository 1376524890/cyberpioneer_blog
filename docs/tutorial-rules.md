# Cyber先锋社博客 · 教程板块规则

本文件定义博客教程体系的内容规划、组织方式与编写规范。所有参与教程撰写的社员请先阅读本规则。

---

## 一、内容板块规划

博客内容按「分类（category）× 系列（series）」两级组织。**分类是横向的大方向，系列是纵向的成体系课程**。

### 分类总表

| 分类 | 定位 | 现有系列 | 规划中系列 |
| --- | --- | --- | --- |
| **社团动态** | 公告、活动通知、纳新、战报 | — | — |
| **编程教程** | 编程语言与通用编程技能 | Python 入门教程、C++ 入门教程、Java 入门教程 | 数据结构与算法、Git 使用 |
| **网络安全** | CTF、Web 安全、靶场实战 | — | CTF 各方向专题、靶场解析 |
| **技术分享** | 工具、建站、杂谈等单篇技术文 | — | 本站建站记录等即归此类 |
| **AI 应用**（筹备） | 大模型、Agent、AI 工具实践 | 待材料到位后开设 | Agent 入门课程、Prompt 工程 |
| **Web 开发**（筹备） | 前端、后端、部署 | — | HTML/CSS/JS、现代化框架 |

### 系列设计原则

1. **一个系列 = 一门 mini 课程**：有明确的学习目标、循序渐进的篇目顺序（`seriesOrder` 从 1 递增）
2. **每篇 1500~3500 字**：单篇聚焦一个主题，讲透即止；太长拆分
3. **系列开篇写"学习路径"**：让读者知道全系列会学到什么、需要什么基础
4. **每篇结尾有小结 + 小练习**：巩固 + 自检
5. **系列写完在 about 页更新总览表**

## 二、教程编写规范

### 1. Frontmatter 模板

```markdown
---
title: 系列名（N）：本篇主题
published: 2026-10-29
description: 一句话说明本篇内容与适合人群（60字内，列表页展示）
tags: [语言或技术名, 教程]      # 2-3 个
category: 编程教程               # 按上方分类总表选
slug: xxx-tutorial-01            # 与系列名一致，末尾两位序号
series: "Python 入门教程"        # 系列名必须完全一致（含标点）
seriesOrder: 1                   # 系列内序号
---
```

**系列字段注意事项**：

- `series` 字符串在同一系列的所有文章中**一字不差**
- `slug` 用英文短横线；同一系列统一前缀（如 `python-tutorial-01/02/03`）
- 中途插入篇目时，`seriesOrder` 允许重排（构建自动按序号排列）

### 2. 内容要求

- **代码必须可运行**：所有示例代码发布前本地跑一遍，附上预期输出
- **原创表达**：知识点可参考任何资料，但**文字、示例、结构必须原创**。禁止整段搬运菜鸟教程、W3School、CSDN 等站点内容——法律风险 + 不利于社团声誉。参考他人思路时，文末附「参考来源」
- **版本与时效**：注明适用版本（如 Python 3.12、JDK 21），过时内容及时修订
- **图片**：优先按 `docs/image-prompts.md` 的统一风格生成配图，放文章同名目录
- **代码块标注语言**：\```bash / \```python / \```cpp，保证高亮正确

### 3. 结构模板（建议）

```markdown
## 为什么 / 本篇目标       （动机）
## 正 文 分 节             （核心内容，配可运行示例）
> [!TIP] / [!WARNING]      （穿插提示、避坑）
## 小练习                  （2-3 道）
## 本篇小结                （要点回顾 + 下篇预告）
```

### 4. 安全与合规红线（沿用 README，教程场景特别强调）

- 漏洞利用类教程**必须**限于合法靶场/授权场景，附免责声明
- 不发布真实攻击载荷、内部系统信息、未脱敏数据
- 不收录需要破解/盗版才能复现的环境

## 三、投稿与发布流程

1. **选题认领**：在社团群里认领系列与篇目，避免撞车
2. **写作**：按本规则起草，文件放 `src/content/posts/`
3. **自测**：本地 `pnpm build` 确认构建通过，`pnpm dev` 检查排版
4. **互审**：至少一位其他社员读过并反馈（先在群里完成）
5. **提交**：按 README 流程 push → 服务器执行 `bash scripts/deploy.sh`
6. **勘误**：发现错误直接修改重新发布，文末更新「最后修订」说明

### Commit 规范（教程场景）

| 前缀 | 场景 |
| --- | --- |
| `post: Python教程(一)初稿` | 新增篇目 |
| `post: 修正C++教程编译命令笔误` | 勘误修订 |
